# Demo UAT

Latest verification: 2026-11-21, recorded below. The following baseline and
performance sections describe the historical 2026-10-22 run.

The static site is generated by `tools/build_site.py --fixtures` from
`tools/render_site.py` and `tools/render_workflows.py`. Serve `docs/` over
HTTP. This run used `http://localhost:4192` and installed Google Chrome.

## Baseline flows

Run `NODE_PATH=<existing Playwright package directory> node tools/demo_uat.cjs`.
Set `UAT_URL` to use another local server. The script uses installed Chrome,
writes screenshots and results to ignored `uat-screenshots/`, and fails on
page overflow, hidden jump destinations, JavaScript errors or failed downloads.
No dependency installation is part of this check.

- Select every demo; exactly one article must be visible.
- Use every section button; focus must reach the section below the sticky controls.
- Check phone (375×812), tablet (768×1024) and desktop (1280×800).
- Open sample sources, download and parse JSON, and activate a jump with the keyboard.
- Load an unknown hash; the evidence demo must appear.

## Results

All 14 demos passed at all three sizes: 78 section jumps, no page overflow
and no JavaScript errors. The microbiome tables need no horizontal swipe.
JSON downloaded and parsed. Tab/Enter activated the Study jump.

The scroll comparison uses measured section positions, not an assumed swipe
length. Native select interaction counts vary by operating system. This run
establishes improvements for these tasks, not a globally minimal interface.
Limits remain open and replay scope remains visible. Buttons wrap instead of
requiring horizontal swipes. No swipe-only controls were added.

## Performance

The generated HTML is 427,719 bytes, about 60 KB gzipped. It makes no external
font, script or data requests during page load. An inline empty favicon avoids
a failed favicon request. CPU-throttled local Chrome (4× slowdown) loaded in
37 ms, with DOM content ready in 19 ms; the section jump also succeeded.
These are single-run local diagnostics, not phone network or field metrics.
Network emulation did not affect localhost reliably, so no simulated mobile
network result is claimed. The static host must enable compression to obtain
the gzip transfer size; the local Python server does not.

## Verification — 2026-11-21

The current procedure uses `npm ci --ignore-scripts`, then
`npx --no-install playwright install chromium`. Serve `docs/` on loopback and
run `npm run uat` followed by `npm run uat:journeys`. Set `UAT_URL` for the
local server. Both scripts default to Playwright's Chromium;
`UAT_BROWSER_EXECUTABLE_PATH` selects an installed browser. The engineering
instructions are in `.agents/skills/site-journey-audit/SKILL.md`.

This run used Playwright 1.58.2 from an existing local installation and an
installed Chrome 158.0.8127.36 override. Screenshots and machine-readable
results are in ignored `uat-screenshots/`. CI installs the locked package
and Chromium and runs both scripts on pull requests and pushes to main.

The functional check passed 38 demos at each of three viewport sizes:
375×812, 768×1024 and 1280×800. It exercised 216 section jumps, thirteen
worksheet downloads, JSON parsing, keyboard navigation and the Daymet
CSV/metadata checksum pair. There were no page errors or page overflow.

The journey check passed eighteen paths: six endpoints at each viewport.
It verified 281 local link targets and fragments across five documents.
External links were counted but not probed. There were no browser errors
or failed first-party requests.

## Application follow-up — 2026-11-21

The dedicated application change adds three recorded bundle journeys at
375, 768 and 1280 pixels. Each starts at the homepage, opens Applications,
uses the page contents to reach one application, and downloads its complete
bundle. Each phone path takes three clicks and no wheel actions. Downloads
use descriptive filenames and their bytes match the generated ZIP files.
The forecast, weather and notice examples retain their scope and limits.

All 27 journeys passed. The link check now reads every generated HTML page:
350 local href targets and fragments across nine documents passed. Browser
and first-party request errors remained at zero. The original selector,
download and repeated-navigation checks still run on pull requests and
pushes to main. The three application presets also passed from an installed
wheel outside the checkout. An independent Croissant reader recovered all

The Regulations.gov path is deliberately gated and not counted as a working

## GCAM receipt follow-up — 2026-11-21

The GCAM application adds three browser journeys. Each opens the application,
downloads its bundle, then downloads and checks the selection plan, receipt
JSON, receipt CSV and pair assessments. All 30 journeys passed across phone,
tablet and desktop widths. The existing demo selector, stability and download
checks also passed. Source receipts preserve step-scoped evidence and region
mappings; the selected Indonesia row uses Southeast Asia.

The physical-click helper now tests each hit rectangle of a wrapped inline
link. Its earlier bounding-box centre could land on whitespace or another
link. Download observation and clicking are awaited together so a failure
produces an audit report instead of an unhandled promise rejection. These
changes preserve real click and scroll counts; they do not use forced clicks.

The receipt links now sit before the GCAM tables. This removes the need to
scroll through those tables to download the selection plan and source
receipts. The full audit path checks five downloads, so its action count is
not the same task as downloading only the bundle.
