Applications built on DOE-MCP

These local command-line applications use read-only tools or declared input files. Examples use recorded publisher responses or clearly labelled synthetic simulations. They are not live services. Download a complete sample bundle or run a command to create your own.

A server hosts tools. A tool returns data and provenance. A skill describes a tested workflow. An application combines tools or declared inputs and writes a result bundle. Installation and application options · Servers · Tool reference · Scientific skills

Recorded site examples normalize replay retrieval clocks and request IDs for repeatable builds. The normalized clock is not a capture date. Source data and fixture hashes are preserved. CLI runs preserve their original tool envelopes.

Forecast input CSV · Scored rows

For your forecasts, pass --forecasts path/to/forecasts.csv and an explicit --actual-timezone when the publisher timestamps lack offsets. An unscored run retains exclusions and does not claim calculated metrics.

Scope and limits

  • Actuals are BPA timestamped five-minute sample MW readings, not interval means.
  • Issuance times are supplied assertions; this application cannot prove forecasts existed before their targets.
  • Persistence uses only observations at or before issuance; gaps and unavailable targets are excluded with reasons.
  • Scores compare each model and lead on its own matched rows; differing match sets are not a controlled model comparison.
  • The sample forecasts were created retrospectively from recorded BPA readings; they are not publisher forecasts or evidence of prospective performance.
  • Unlabelled BPA Pacific clock readings use the supplied IANA timezone assumption; the publisher did not supply an offset for each reading.

Download the plan, edit its exact filters and selected columns, then run:

doe-mcp app gcam-comparison --plan ./plan.json --output ./gcam-custom

Scope and limits

  • These are released GCAM configuration inputs, not observations, current prices, forecasts or scenario outputs.
  • Every selector must match exactly one row. Original decimal strings, categories and null cells are preserved.
  • Country mapping uses the region convention present in the selected table. A country's membership does not make a regional input a country measurement.
  • Unit statements are retained verbatim from publisher table notes. NA or absent statements remain unspecified; source descriptions may give further context.
  • Pairs are side-by-side receipts only. No addition, subtraction, ranking, conversion or aggregation is performed, including for matching table fields.
  • Different tables can use the same year column for unrelated concepts. Read full row qualifiers, release, source notes and region mappings before interpreting a pair.

Research artifact linkage explorer

Recorded example. Runs locally.

doe-mcp app research-linkage --dataset-query EAGLE-I --resolve-relationships --output ./research-linkage-run

Download complete bundle · View report and source evidence · File checksums

Search literature, dataset and software catalogs, then inspect source-linked inventory, shared DOI identity and typed publisher relationship assertions separately. This recorded example follows one EAGLE-I IsPartOf assertion by DOI. The three discovery topics are independent; co-returned records do not establish relationships.

Returned 10 records and 1 explicit publisher assertion. One-hop follow-up used 4 of 4 allowed requests.

Publisher relationship Target DOI Resolution Candidate source records
IsPartOf 10.13139/ornlnccs/1975203 ambiguous osti-data-explorer:1975203; osti-gov-records:1975203

Ambiguous means two source records share the target DOI. OSTI.GOV and DOE Data Explorer both returned a matching record; this does not establish two different artifacts. The receipt retains both candidates and the originating publisher assertion with evidence pointers.

Only the original typed DOI assertions enter follow-up. Exact normalized DOI matching is required; titles, topics, grants and contracts never create edges. Unknown totals, failed sources and request limits cannot establish uniqueness or absence. No DOI landing page, repository or further relationship is fetched.

Inventory CSV · Linkage receipt · Download original assertions and follow-up evidence

Use --live --query YOUR_TOPIC for one topic across the collections, or set separate --literature-query, --dataset-query and --software-query values. --rows and --page-budget bound discovery. Add --resolve-relationships for one hop and --relationship-request-budget 4 to cap follow-up HTTP attempts, including retries and redirects. At most eight distinct original targets are searched. Resolution rules and recorded evidence.

Scope and limits

  • Each collection is searched independently. The recorded preset uses different recorded topics; co-returned records are not relationship evidence.
  • Only exact normalized DOIs establish shared identity. Shared identity does not assert that a paper uses a dataset or software.
  • Explicit links require a typed DOI assertion in the publisher related_identifiers field. Grants, awards, journal prose, titles and authors never create links. Unparsed relationship values are counted.
  • Optional follow-up searches only the original typed DOI assertion frontier in four fixed active research catalogs, under a shared HTTP request budget. It never follows returned assertions or downloads target artifact or repository content.
  • Search scope retains every page's coverage and publisher totals. Unmatched means unmatched within these bounded returned records, not proof that a relationship does not exist.
  • The literature tool deduplicates its two collections by DOI; this inventory preserves its returned rows and original envelope evidence, rather than reconstructing discarded rows.
  • Source text is third-party data. CSV cells that could be spreadsheet expressions are prefixed with an apostrophe; JSON retains original titles.

Import your own declared CSVs with --plan, --actuals and --forecasts. The import preserves raw input hashes and attribution but cannot establish that supplied observations, issuance times or availability times are historically true. A simulation declaration remains simulation on reimport. Input format and measurement rules.

Scope and limits

  • This panel compares declared inputs, not publisher-verified observations. A simulation run does not measure real-world model performance.
  • Every compared model and persistence use the identical eligible target set within each region and lead. Cross-region intersection mode additionally uses the same targets in every declared region.
  • Within-region mode permits different region cohorts. No cross-region aggregate score or ranking is produced in either mode.
  • Availability and issuance timestamps are assertions in the supplied files; their historical truth cannot be established from a CSV.
  • Persistence uses only observations effective and available at or before issuance, within the declared maximum age. Later observations never set its prediction.
  • Quantity, unit, cadence, interval meaning and timestamp meaning must match the declaration. Power samples, interval means and energy totals cannot be mixed; no unit conversion or temporal aggregation is performed.
  • Missing declarations are refused. Missing values, forecasts and observations remain explicit cohort exclusions; a region with no common targets stays in the report with null metrics.

Scope and limits

  • This run reads one pinned ATB electricity edition and release. It does not select a latest edition or blend currency bases.
  • Rows retain publisher technology detail, resource class, metric, scenario, projection year, units, financial case, tax-credit case and capital recovery period. Multiple matches are explicit, not a chosen first row.
  • These are published scenario assumptions, not observed costs, bids, economic advice or a project-specific estimate. Null metric values remain missing.
  • A bounded page is not all matches when pagination is truncated. Refine filters or use the offset for subsequent pages.
  • The full pinned release is verified locally; only selected rows are exported. Publisher row numbers are one-based data rows within those exact bytes.
  • PVWatts remains proposed without a real credential-redacted recording. No model result, API request, DEMO_KEY use or key configuration is part of this application.
  • Source text is third-party data. CSV expression-like text is prefixed with an apostrophe; JSON retains original content.
