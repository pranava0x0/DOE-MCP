Development backlog

Updated 2026-11-21 after PRs 19–26. This is the public development backlog. Items below are plans, not claims that a proposed integration works.

A server hosts tools for a domain. A tool performs one bounded read. A skill explains how to combine tools and interpret their evidence. An application produces an output bundle; a demo shows an example. Extend an existing server when its data domain fits. Add a new server only when its dependency, credential or operating boundary requires one.

Start with the ATB skill: its reader, fixtures and export application already ship, so the next useful addition is guidance that prevents incorrect selection and interpretation. Use Sol for implementation and focused tests; use Astra for scientific contracts and final review. Reserve larger-model reviews for substantive risks rather than routine copy or formatting.

Later work without keys

  • Medium — Tool and application: bounded complete ATB exports. Keep all qualifiers and per-page evidence; stop with explicit incomplete status when a declared row or request budget is exhausted. Never relabel a ten-row page as the complete result.
  • Medium — Weather application: multiple-point package plans with a per-point manifest, units, calendar checks and total request budget. Keep the existing single-point package format usable.
  • Medium — Skill evaluation: import human reviews of existing answers into the matrix. Bind reviews to exact task, rubric and answer hashes. Missing grades stay unknown; no provider account is needed to review supplied answers or compare existing reports.
  • Medium — Accessibility: repeat manual VoiceOver and NVDA checks for material navigation changes. Automated scans and browser accessibility trees are useful regression checks, but do not replace assistive-technology testing or establish full WCAG conformance.
